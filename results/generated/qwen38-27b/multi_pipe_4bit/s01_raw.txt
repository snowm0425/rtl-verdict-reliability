### Verilog Code

```verilog
module multi_pipe_4bit #(
    parameter size = 4
) (
    input  wire              clk,
    input  wire              rst_n,
    input  wire [size-1:0]   mul_a,
    input  wire [size-1:0]   mul_b,
    output reg  [2*size-1:0] mul_out
);

    // Internal signals
    wire [2*size-1:0] partial_products [0:size-1];
    reg  [2*size-1:0] reg_partial      [0:size-1];

    // Generate partial products
    genvar i;
    generate
        for (i = 0; i < size; i = i + 1) begin : gen_partial
            // If mul_b[i] is 1, partial product is mul_a << i
            // Otherwise, 0
            assign partial_products[i] = mul_b[i] ? ({{size{1'b0}}, mul_a} << i) : {2*size{1'b0}};
        end
    endgenerate

    // First level of registers: Store the partial products
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            for (i = 0; i < size; i = i + 1) begin
                reg_partial[i] <= {2*size{1'b0}};
            end
        end else begin
            for (i = 0; i < size; i = i + 1) begin
                reg_partial[i] <= partial_products[i];
            end
        end
    end

    // Second level of registers: Sum the registered partial products and store in mul_out
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            mul_out <= {2*size{1'b0}};
        end else begin
            // Sum all reg_partial[i]
            reg [2*size-1:0] sum;
            sum = reg_partial[0];
            for (i = 1; i < size; i = i + 1) begin
                sum = sum + reg_partial[i];
            end
            mul_out <= sum;
        end
    end

endmodule
```

### Explanation

1.  **Parameterization**: The module uses a `size` parameter (default 4) to define the width of the inputs and the output width (`2*size`).
2.  **Partial Product Generation**:
    *   A `generate` block iterates from `0` to `size-1`.
    *   For each bit `i` of `mul_b`, it checks if `mul_b[i]` is `1`.
    *   If `1`, the partial product is `mul_a` shifted left by `i` positions. The shift is done on an extended version of `mul_a` (zero-extended to `2*size` bits) to ensure correct bit width.
    *   If `0`, the partial product is `0`.
3.  **First Register Stage (`reg_partial`)**:
    *   An `always` block triggered on the positive edge of `clk` or negative edge of `rst_n`.
    *   On reset, all `reg_partial` registers are set to `0`.
    *   Otherwise, the combinationally generated `partial_products` are stored in `reg_partial`. This is the first level of pipeline registers.
4.  **Second Register Stage (`mul_out`)**:
    *   Another `always` block, also triggered on `clk` and `rst_n`.
    *   On reset, `mul_out` is set to `0`.
    *   Otherwise, it sums all the values in `reg_partial` (which now hold the partial products from the previous cycle) and stores the result in `mul_out`. This is the second level of pipeline registers.

### Pipeline Timing

*   **Cycle 1**: `mul_a` and `mul_b` are input. Partial products are computed combinationally.
*   **Cycle 2**: Partial products are latched into `reg_partial`.
*   **Cycle 3**: The sum of `reg_partial` is computed and latched into `mul_out`.

Thus, the output `mul_out` reflects the product of the inputs from **two clock cycles ago**.
