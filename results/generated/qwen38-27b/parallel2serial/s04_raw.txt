Here is the complete Verilog code for the `parallel2serial` module, strictly following your implementation requirements.

```verilog
module parallel2serial (
    input        clk,
    input        rst_n,
    input  [3:0] d,
    output reg   valid_out,
    output       dout
);

    // Internal registers
    reg [3:0] data;
    reg [1:0] cnt;

    // Assign serial output: MSB of data register
    assign dout = data[3];

    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            // Reset state
            data <= 4'b0000;
            cnt  <= 2'b00;
            valid_out <= 1'b0;
        end else begin
            if (cnt == 2'd3) begin
                // Last bit of current sequence
                // Update data with new parallel input
                data <= d;
                // Reset counter to 0 for next sequence
                cnt <= 2'b00;
                // Valid signal high for this cycle (outputting d[3])
                valid_out <= 1'b1;
            end else begin
                // Middle bits of sequence
                // Increment counter
                cnt <= cnt + 1'b1;
                // Valid signal low for subsequent bits
                valid_out <= 1'b0;
                // Shift data left, MSB to LSB
                // Example: 4'b1011 -> 4'b0111 (next cycle dout will be 0, then 1, then 1)
                data <= {data[2:0], data[3]};
            end
        end
    end

endmodule
```

### Explanation of Behavior

1.  **Reset (`rst_n = 0`)**:
    *   `data` is cleared to `4'b0000`.
    *   `cnt` is cleared to `2'b00`.
    *   `valid_out` is cleared to `0`.

2.  **Normal Operation (`rst_n = 1`)**:
    *   **Cycle 1 (`cnt = 0`)**:
        *   Since `cnt != 3`, the `else` block executes.
        *   `cnt` becomes `1`.
        *   `valid_out` becomes `0`.
        *   `data` shifts left: `data <= {data[2:0], data[3]}`.
        *   `dout` outputs the current `data[3]` (which was set in the previous cycle when `cnt` was 3).
        *   *Note: In the very first cycle after reset, `data` is 0, so `dout` is 0. The first valid data output occurs after the first time `cnt` reaches 3 and updates `data`.*

    *   **Cycle 2 (`cnt = 1`)**:
        *   `cnt` becomes `2`.
        *   `valid_out` remains `0`.
        *   `data` shifts left again.
        *   `dout` outputs the next bit.

    *   **Cycle 3 (`cnt = 2`)**:
        *   `cnt` becomes `3`.
        *   `valid_out` remains `0`.
        *   `data` shifts left again.
        *   `dout` outputs the next bit.

    *   **Cycle 4 (`cnt = 3`)**:
        *   Since `cnt == 3`, the `if` block executes.
        *   `data` is loaded with the current input `d`.
        *   `cnt` resets to `0`.
        *   `valid_out` is set to `1`.
        *   `dout` outputs `data[3]`, which is now `d[3]` (the MSB of the new input). **This is the first valid bit of the new sequence.**

3.  **Timing Diagram Example**:
    Assume `d` is continuously `4'b1011` (11 decimal).

    | Cycle | clk | rst_n | d      | cnt (start) | data (start) | valid_out | dout | Action                     |
    |-------|-----|-------|--------|-------------|--------------|-----------|------|----------------------------|
    | 0     | 0   | 0     | x      | 0           | 0000         | 0         | 0    | Reset                      |
    | 1     | 1   | 1     | 1011   | 0           | 0000         | 0         | 0    | cnt->1, valid->0, shift    |
    | 2     | 1   | 1     | 1011   | 1           | 0000         | 0         | 0    | cnt->2, valid->0, shift    |
    | 3     | 1   | 1     | 1011   | 2           | 0000         | 0         | 0    | cnt->3, valid->0, shift    |
    | 4     | 1   | 1     | 1011   | 3           | 0000         | 1         | 1    | **Load d**, cnt->0, valid->1 |
    | 5     | 1   | 1     | 1011   | 0           | 1011         | 0         | 0    | cnt->1, valid->0, shift    |
    | 6     | 1   | 1     | 1011   | 1           | 0111         | 0         | 1    | cnt->2, valid->0, shift    |
    | 7     | 1   | 1     | 1011   | 2           | 1111         | 0         | 1    | cnt->3, valid->0, shift    |
    | 8     | 1   | 1     | 1011   | 3           | 1111         | 1         | 1    | **Load d**, cnt->0, valid->1 |

    *   **Cycle 4**: `valid_out` is high. `dout` = `1` (MSB of `1011`).
    *   **Cycle 5**: `valid_out` is low. `dout` = `0` (next bit).
    *   **Cycle 6**: `valid_out` is low. `dout` = `1` (next bit).
    *   **Cycle 7**: `valid_out` is low. `dout` = `1` (LSB).
    *   **Cycle 8**: `valid_out` is high. `dout` = `1` (MSB of next `d`).

    The serial output sequence for `d=1011` is `1`, `0`, `1`, `1` over 4 cycles, with `valid_out` high only on the first bit of each group.
